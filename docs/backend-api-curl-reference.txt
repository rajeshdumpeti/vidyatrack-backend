VidyaTrack Backend API Curl Reference

Purpose
- This document is the copy-paste API script reference for the current backend.
- Use it to validate endpoints in Postman before validating from the UI.
- When any request payload or query shape changes in the backend, update the matching curl block here.

Base URL
- Local default: http://127.0.0.1:8000/api/v1

Recommended placeholders
- Replace YOUR_JWT_TOKEN_HERE with a real bearer token from /auth/otp/verify
- Replace school_id values with a school the user can access
- Replace IDs such as student_id, section_id, subject_id, teacher_id, class_id with valid values from your environment

Postman usage
1. Open Postman.
2. Click Import.
3. Choose Raw text.
4. Paste one curl command from this document.
5. Click Import.
6. Save it into a collection, for example Backend Smoke Tests.
7. Edit the URL, token, query params, or request body as needed.
8. Repeat for other commands.

Recommended Postman environment variables
- base_url = http://127.0.0.1:8000/api/v1
- token = paste JWT here
- school_id = valid school id
- student_id = valid student id
- section_id = valid section id
- subject_id = valid subject id
- teacher_id = valid teacher id
- class_id = valid class id
- attendance_id = valid attendance id
- draft_id = valid school onboarding draft id
- principal_session_id = valid principal onboarding session id

If you prefer Postman variables, replace:
- http://127.0.0.1:8000/api/v1 with {{base_url}}
- YOUR_JWT_TOKEN_HERE with {{token}}

Auth flow

1. Request OTP
curl --location 'http://127.0.0.1:8000/api/v1/auth/otp/request' \
--header 'Content-Type: application/json' \
--data '{
  "phone": "9876543210"
}'

2. Verify OTP
curl --location 'http://127.0.0.1:8000/api/v1/auth/otp/verify' \
--header 'Content-Type: application/json' \
--data '{
  "phone": "9876543210",
  "otp": "1234"
}'

3. Get current auth user
curl --location 'http://127.0.0.1:8000/api/v1/auth/me' \
--header 'Authorization: Bearer YOUR_JWT_TOKEN_HERE'

4. Auth debug me
curl --location 'http://127.0.0.1:8000/api/v1/auth/me' \
--header 'Authorization: Bearer YOUR_JWT_TOKEN_HERE'

Useful notes
- Many endpoints require Authorization and a school mapping for the supplied school_id.
- If an endpoint uses get_valid_school_id, you must pass school_id in query params and the JWT user must be mapped to that school.
- School onboarding and school create flows can create multiple records and may require clean seed data in local environments.
- Student import preview requires multipart form upload, not JSON.
- Some teacher endpoints are role-protected and only work for TEACHER users.

Recommended smoke order
1. /health/live
2. /health/ready
3. /auth/otp/request
4. /auth/otp/verify
5. /auth/me
6. /management/dashboard or /principal/dashboard depending on role
7. list endpoints for school-scoped resources
8. create endpoints only after list endpoints confirm valid IDs
